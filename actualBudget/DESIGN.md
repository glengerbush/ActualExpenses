# actualBudget interface

Scope: web only. Android PRODUCT/DESIGN remain separate. Approved specification supplies product truth; routine visual decisions are delegated, not a new user-approved brand identity.

## Direction
Operate mode, code-first. Restrained everyday financial workspace: warm white work area, pale neutral navigation, dark ink, forest-green selection/action, red only for errors. Direction follows the delegated task-first brief; no marketing concept ceremony. Impeccable direction seed considered: seed:3b69783ecc04a390.

## Structure
Budget chooser leads first use. Once selected, a compact sidebar holds the budget and accounts, while the main area contains account balances or a single inline creation form. Mobile stacks navigation above content. No empty feature navigation or decorative metrics.

## Type and spacing
System sans, fixed rem scale; 16px body, 24–30px headings. Tabular monetary figures, right-aligned balances. Space groups by 8px rhythm. Use lines and surface changes rather than floating cards. Controls have at least 44px touch targets.

## Interaction
Native inputs and selects, visible focus rings, associated hints/errors. Inline forms preserve values on failure. Pending mutations disable repeat submission. Retry preserves the request identity and payload. Server confirmation precedes changing visible balances. Explicit text for loading, empty and error states. No decorative animation.

## Tokens
See web/src/styles.css for authoritative values. Accent is reserved for actions/selection. Color does not carry meaning alone. Layout collapses at 700px; type does not shrink on mobile.
