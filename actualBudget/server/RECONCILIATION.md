# Reconciliation contract

Capabilities: `reconciliation`, `reconciled_confirmation`, `reconciliation_cancellation`. Public routes and schemas live in `src/openapi.json`.

`GET /api/v1/budgets/{budget}/accounts/{id}/reconciliation?statement_balance={minor_units}` returns exact total/cleared/uncleared balances, signed difference, locked/ready/uncleared counts, account last-reconciled timestamp, a snapshot cursor and observed edit clock. Omitted statement balance defaults to cleared. All dates participate, matching Actual26.10.0; register date/filter controls do not narrow reconciliation. Debt balances stay negative.

POST the same resource with `{action, statement_balance, snapshot, date}`. `lock` requires zero difference and current snapshot; it marks cleared entries reconciled and records current wall-clock milliseconds as account `last_reconciled`. `adjust` additionally requires a stable `transaction_id`; it creates a cleared, unreconciled transaction for statement minus cleared balance, on the supplied date, with notes “Reconciliation balance adjustment”. On-budget and off-budget accounts permit adjustment. Categories remain unset; asset revaluation does not become on-budget income. Zero adjustments are rejected.

POST `/api/v1/budgets/{budget}/transactions/{id}/unlock` with `{reconciled_version}` to remove protection explicitly. The submitted version must equal current protection version; the intent HLC must exceed it. Cleared status remains unchanged. Account reconciliation history remains intact.

Ordinary PATCH accepts `confirm_reconciled: true` and the displayed transaction’s `reconciled_version` alongside edited fields. The confirmation is part of immutable request identity, is not an editable ledger field, and leaves protection intact. The captured protection version must exactly match the current row, and the immutable edit HLC must exceed that version. A later unlock/relock invalidates the old confirmation even if its amount/notes field would otherwise win. Missing proof safely refuses a locked edit; already-committed receipts (including older payload shapes) replay before this check. Field ordering still applies. Unconfirmed edits and deletion are rejected while locked; deletion requires explicit unlocking. Existing published-tombstone merge semantics remain unchanged.

All financial effects, timestamps, field clocks, changes and operation receipts commit atomically. New actions require matching budget generation; original receipts replay before generation/snapshot checks. Cancel using the original method/path/body/key/clock/epoch plus `X-Actual-Cancel-If-Uncommitted: true`; original committed outcome wins, otherwise durable cancellation fences delayed originals. Five-minute future clocks are rejected without consuming the request. Clients retain rejected clocks and pending identities until unchanged retry or explicit cancellation. Statement previews carry the server's observed HLC so locking also works when relevant rows lie outside the visible register page.

Schema10 (provisional until root integration) adds nullable `accounts.last_reconciled`. Import preserves the source's millisecond text and maps its field clock without rewriting it. New upload intent can re-inspect a pre-reconciliation blocked stage; original upload receipt stays immutable. Native archives retain this field, validate timestamps, and accept older schemas6–9 with null default. Confirmed edits, unlock, restart and restore retain dates and protection.

Integration requirements: split parents own balances/counts; locking/unlocking must propagate to all children and their status clocks. Transfer confirmation must capture a per-transaction version map and call `protect(row, Some(Confirmation { version, clock }))` separately for both changed protected legs, while reconciliation/unlock remains account-local. Bulk/undo must inspect every protected affected row. Ticket12 supplies cleared/reconciled visibility filters. Provider balance selection and adjustment rule execution join when those feature tickets land; credentials never join reconciliation responses.
