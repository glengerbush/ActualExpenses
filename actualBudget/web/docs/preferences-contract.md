# Preferences contract (ticket 43)

Shared budget preferences: `GET /api/v1/budgets/{budget}/preferences` returns `{data:{number_format,date_format,hide_fraction,first_day_of_week,currency_code,currency_symbol_position,currency_space,experimental,revision}}`.

`PATCH` same path, required Idempotency-Key, JSON partial changes at the top level. Unknown fields rejected. Null resets a named field to its default. `experimental` is a partial map of baseline flag names to booleans; unspecified flags remain unchanged, null resets all flags. Writes are atomic and replay-safe. Separate changes from concurrent clients do not overwrite unrelated fields.

Defaults: comma-dot, MM/dd/yyyy, false, 0 (Sunday), empty currency, before, false; all experimental flags false. Supported number formats: comma-dot, dot-comma, space-comma, apostrophe-dot, comma-dot-in. Dates: MM/dd/yyyy, dd/MM/yyyy, yyyy-MM-dd, MM.dd.yyyy, dd.MM.yyyy, dd-MM-yyyy. Currency codes/symbols/precision match pinned Actual currencies.ts (IRR/JPY/KRW precision0, others2).

Device preferences stay in origin-scoped localStorage: theme(light/dark/midnight/system), preferred_dark_theme(dark/midnight), language(empty means browser default). They never enter shared preference mutations. Display changes do not modify stored financial units or ISO calendar dates.

`POST /api/v1/preferences/convert-actual` is a read-only conversion endpoint: `{synced:{...rawActualKeys},global:{...rawGlobalStoreKeys}}` -> `{data:{shared,device,warnings,unmapped}}`. It accepts no credentials/encryption settings as active preferences. Unsupported custom theme data remains in unmapped with a warning for ticket44. Ticket04 must call the same converter within full archive import; this endpoint alone does not implement archive import.

Frontend: `preferences.startDevice(): () => void` initializes local appearance/language and system-theme listener; `await preferences.loadBudget(id)` loads shared values with per-budget cached fallback and visible error state. `preferences.shared`, `.device`, `.error` are reactive. `Settings.svelte` props budgetId/onclose. Natural-key `t(key, params?)` from i18n.svelte.ts escapes via ordinary Svelte text; never rawHTML. Money helpers: formatAmount(integer), formatDate(ISO), formatAmountInput(integer), amountDecimalPlaces(), normalizeAmountExpression(string). They read current shared preferences; normalize only locale notation, leaving arithmetic to the API.

## Recovery and availability

Shared settings changes use an origin- and budget-scoped version1 durable draft. The exact partial body and stable draft UUID/idempotency key are persisted before PATCH. Reload restores an unconfirmed request without sending it automatically; retry sends the same bytes and identity. Device settings persist before applying. Storage failures remain visible and prevent new durable writes. Done preserves a draft; Discard removes only safe unsubmitted changes. Local caches are optional. A failed refresh can use validated cached settings; with no validated settings, financial display/new entry is blocked so an unknown zero-decimal currency cannot be misinterpreted. Previously captured pending account/transaction bodies remain retryable.

Money entry drafts capture number format and currency precision. Display preferences cannot reinterpret a saved request. Input retains exact fractions even when display hides them; changing only notes never rounds the original integer amount. Date entry accepts the selected format, baseline month/day and short-year abbreviations, and unambiguous ISO dates. Raw input remains intact until blur/Enter; invalid drafts survive reload. Its calendar honors week start and supports arrows, Home/End, PageUp/PageDown, Escape and keyboard selection. The pinned-source date fixture covers all six formats and the baseline's rolling short-year window without adding a production date library.

## Languages and provenance

The 15 catalogs are extracted byte-for-byte from the locked published `@actual-app/web@26.10.0` sourcemaps by `python3 actualBudget/tools/extract-locales.py`. `src/locales/provenance.json` records package integrity and individual map/catalog hashes; MIT license retained alongside them. Currency metadata is adapted from the immutable 26.10.0 `shared/currencies.ts` under the same MIT license.

English uses natural keys plus a small generated plural subset. Other catalogs load lazily only when selected; none are loaded for default English. Existing shipped translations and semantically equivalent label aliases are reused. New recovery/explanatory text falls back to English where the released catalogs have no key: this is supported language selection, not a claim that every new sentence is translated. Region fallback matches Actual: exact available locale, then available base language, otherwise English; `zh-CN`/`zh-TW` fall back to English unless users choose the shipped `zh-Hans`/`zh-Hant` explicitly. Coverage report: `docs/translation-coverage.json`.

The 220 monetary expectations in `tests/fixtures/preferences-format-26.10.0.json` are generated by executing pinned Actual formatter source, independently of the replacement. Reproduce/check with `node tests/generate-preferences-fixture.mjs --check`. Browser acceptance compares all expectations through running HTTP API and rendered account balances, including negative half ties and JPY. All browser suites run through `npm run test:browser` against fresh isolated data; an explicit `ACTUALBUDGET_TEST_URL` must point only to an isolated test server.

Currency display requires `experimental.currency=true`. Disabled state normalizes `currency_code` to empty on read, mutation and Actual preference conversion, matching the baseline Settings clear-code effect. The UI hides currency controls while disabled; disabling does not reset number format or hide-fraction preferences. Existing captured draft precision and pending request bodies remain unchanged across flag toggles. The formatter also ignores stale cached currency codes when the flag is false.
