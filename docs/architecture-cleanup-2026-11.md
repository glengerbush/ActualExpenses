# Retired-feature architecture cleanup

All six approved candidates were implemented. The architecture review targeted dead execution paths after the simplified manual-budget workflows replaced the original feature set.

- Removed orphan account navigation/view components and Android snapshot decoder.
- Old account URLs now open only existing durable recovery work, otherwise Transaction history. Unreadable storage still reaches recovery diagnostics.
- Removed unreachable tag mutations, parsing, query filtering and SQLite tag function. Historical tag records remain available to source/archive validation.
- Removed impossible currency-provenance states. Kept provenance needed to validate existing archives.
- Preference writes resolve exact committed receipts before validating new input; retired preferences cannot be recreated by a fresh request.
- Android migration uses a pure released-state decoder. The old network client and snapshot/protobuf support moved from production to test source. Original queued bodies, clocks, identities and fixture bytes remain unchanged. Differential tests compare all four genuine upgrade fixtures with the frozen old client.
- Migration36 retires note-only or note-dependent rules and their schedules, while preserving financial actions in mixed rules. Unactivated imports are reviewed again; source bytes, field clocks and receipts stay intact. Saved note filters remain inactive rather than becoming broader financial filters.
- Migration35 repairs overly broad note-month guards without resurrecting previously deleted text. Arbitrary public note identities remain compatible.
- Unmounted custom-report loaders cannot persist stale state over newer work. A delayed-read regression proves that the exact draft and immutable retry operation survive navigation, cancellation, reload and cache reset.
- Silent queued edits now follow dependency/clock order rather than random UUID order; the register displays and edits the latest local intent.
- Released settings drafts can replay exact retired-only receipts, including original currency and experimental preferences. Fresh retired writes remain rejected.
- Reconciliation timestamps cannot return through source import or native restore. Invalid historical timestamps still fail validation; original archive bytes and receipts remain untouched.

Qualification follows the current interface. Mixed tests retain financial results, field-ordering, idempotency, cancellation, outbox, archive and recovery assertions. Concurrency workloads formerly changing notes/status now change supported amounts or dates. Tests solely executing removed lock workflows or experimental reports are removed; source history remains in Git. Genuine old schemas and archived receipts remain exercised. Tests no longer fake old schemas by merely lowering `user_version` on a new database with new triggers.

Keep: historical account identities, transfer pairs, financial source fixtures, retained raw archives, native backups, outbox and exact receipts; recurrence modules; report Markdown rendering. These still have live callers or compatibility obligations. Larger speculative restructuring would add risk without eliminating more dead behavior.
