## Current official protocol boundary

The [official protocol](https://www.simplefin.org/protocol.html) currently labels v2 as draft. Claim is one-use POST; its Access URL contains Basic credentials. HTTPS/certificate checks and sanitized messages are required. `/accounts` uses inclusive start/exclusive end timestamps, repeated account filters, optional pending/balances-only and explicit version. Account/transaction identities are scoped, not global. HTTP402/403 and structured `errlist` errors must remain distinct; `act.missingdata` denotes incomplete listings. Legacy `errors` strings are deprecated. The pinned adapter instead expects v1 `org`/`errors`: explicitly choose supported versions and test compatibility; do not trust a changing server default.

The [Bridge developer guide](https://beta-bridge.simplefin.org/info/developers) expects at most24 requests/day, replenished through the day; all-account and individual-account quotas differ. Warnings may precede disabled access. Requests span at most90 days; available history varies. It recommends roughly five-day overlap. These are Bridge limits, not universal protocol quotas. The protocol defines no continuation cursor: do not invent SimpleFIN pagination; test bounded date windows and incomplete responses. No stated universal response-size/timeout ceiling was found; replacement limits must be explicit and fail without partial financial application.

## Shared seam to establish in28

1. **Connection lifecycle:** stable local connection ID, provider discriminator, credential generation/reference, remote connection/account mapping, nonsecret state and last successful refresh. Link/relink/unlink/token replacement are explicit atomic commands. Unlink preserves purchases/import IDs; it clears connection/balance metadata, not financial history. Replacing credentials must fence in-flight work using the old generation.
2. **Fetch outside the ledger transaction:** provider adapter returns bounded raw account sets, normalized candidate records, balance/date/currency, completeness and sanitized per-account errors. Persist a retained refresh batch and its original context before financial apply. Resume a committed batch by receipt; never refetch changed provider data under an old immutable command. Provider network fetch and local atomic commit are separate recoverable phases.
3. **Financial apply:** share guarded rules-before-match, payee creation, split/transfer writes, imported-ID matching, HLC/history/feed and epoch protections from25/26. Keep a bank-specific normalization entry point/preferences: source bank notes escape `#`, support payment/deposit mappings and booked transitions, and can update dates. Pending→booked may change remote IDs; never infer permanent identity from amount/date alone. Preserve source candidate competition and deleted-reimport semantics through executed source cases.
4. **Balances:** retain provider balance separately from computed ledger/reconciliation balances. Source first sync derives an opening amount from current balance minus downloaded entries unless explicitly overridden; subsequent refresh updates provider balance without silently inserting an adjustment. Verify zero/one/two-decimal strings, liability signs, future/date boundaries, pending inclusion and initial existing-account linking. Source `replace('.', '')` arithmetic and hardcoded USD in its SimpleFIN translator are hazards requiring explicit evidence/decisions, not copied financial formulas.
5. **Secrets:** server-only credential store, write-only replacement API and nonsecret status. Generic operation payloads/receipts, history, changes, native/browser exports, logs, exceptions and URLs must never expose setup tokens, Access URLs or Authorization. Use a request fingerprint/secret reference for replay, not a persisted plaintext secret body in ordinary receipts. Retain claimed credentials durably before acknowledging; one-use claim ACK loss cannot be solved by blindly claiming again. Source secret debug logging includes values: do not port it. Redact provider text and URL userinfo; validate each outbound redirect/address, stripping cross-origin auth. External provider HTTPS is separate from supported plain-HTTP app LAN access; fixture/self-host HTTP exceptions require explicit scope.
6. **Migration:** current `server/src/imports/conversion.rs` blocks `account_configuration` for bank fields. Add lossless provider metadata/per-field-clock conversion, preserve originals and require credential re-entry when server secrets are unavailable. Do not unblock later providers merely because28 exists. Native archive/duplicate/restore must preserve mappings/preferences and rotate existing epoch fences; ordinary archives must not become secret exports. Source global credentials need an explicit mapping to new connection scope.
