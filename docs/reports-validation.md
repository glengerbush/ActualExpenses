## API / persistence

- `GET /api/v1/budgets/{budget}/reporting`: documents with revision, epoch and snapshot. Kinds `page`, `widget`, `custom_report`; configs retain source-shaped fields and future metadata.
- `POST .../reporting/commands`: atomic `{writes:[{id,kind,revision,config,tombstone}]}`,1–200 writes. Revision0 means absent; per-document CAS rejects independently newer settings. Require immutable idempotency key + budget epoch; optional HLC must not precede existing document ordering. Preserve source clocks, stamp changed documents with server-owned advanced HLC. Exact body/key/epoch retries, receipt lookup and durable cancellation fences. Even rejected domain drafts can be canceled. Local draft/request/epoch/cancellation phase persists across reload/cache reset; conflict retains intent.
- `POST .../reports/query`: version1, kind, explicit as_of and options.33 kinds cash-flow/net-worth/spending/summary/calendar plus live `range` and `widget-range`. Complete source financial output plus server-issued inspectable cells and snapshot. Typed served OpenAPI describes request/result variants.34 adds `custom`, complete source metrics/interval/group shapes and optional nested `groupedData`. `recorded` plus `basis` distinguish recorded transactions, planned budget allocations and date resolution.
- `POST .../reports/drilldown`: same validated query, snapshot, cell_id, offset, limit1–200. Stable date/ID order, matching sign/account/split/group inclusion.34 adds `record_kind`, nullable account IDs and composite allocation IDs (`method:month:category`), with explicit planned-allocation labels. Snapshot change rejects the page. Summary/average inspection identifies its underlying recorded entries; its sum is distinct from a displayed average/ratio.

Bounds reject rather than truncate:3660 daily or1200 coarser output intervals,500 selected accounts,20000 financial/inspection cells,100000 matching projected ledger entries,50000000 row/bucket evaluations and exact safe monetary flow. Sparse long histories remain supported for monthly/yearly and all-time modes; no blanket elapsed-year or widget-date-window cutoff. Conditions may narrow very large scans. Backend scans bounded projected rows, not browser history; the explicit100000-row input bound remains a limitation for very large histories.

Schema22 adds only `reporting_documents`; archive/delete/duplicate/restore/recovery registry includes it. Native inspection reports the normalized current schema22; corresponding existing assertions updated, original fixture bytes/version metadata unchanged. Source-only legacy dashboard/report records enrich from preserved originals. Reporting performs no ledger monetary mutations.
